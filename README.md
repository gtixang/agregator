# 📚 Agregator — агрегатор онлайн-курсов

Agregator — фронтендное веб-приложение на Angular, цель которого — помочь пользователю находить, фильтровать и просматривать онлайн-курсы и школы. Проект находится в активной разработке: множество ключевых функций уже реализовано, но работа продолжается.

🔗 Демо: https://agregator-nu.vercel.app/

---

## ✨ Что реализовано (на текущей ветке)
(Перечислено только то, что реально присутствует в кодовой базе и доступно через UI)

- Каталог курсов с серверной выборкой из Supabase
- Фильтрация курсов по цене, длительности, уровням, школам и дополнительным параметрам (интернатура, сертификат)
- Категории / вкладки тем (topics)
- Сортировка курсов (компонент управления сортировкой присутствует)
- Пагинация и асинхронные состояния (pending / ready / empty / error)
- Страницы: главная, список курсов, детали курса, список школ, отзывы, 404
- Виджеты: header, footer, список курсов, список школ, список отзывов
- Просмотр информации о школе и карточки курсов
- Отзывы: просмотр и форма создания отзыва (частично реализовано)
- Интеграция с Supabase через сервис (`SupabaseService`) и data-access слои для сущностей
- Feature-Sliced Design: папки `pages`, `widgets`, `features`, `entities`, `shared`
- Настроены инструменты качества кода: ESLint, Prettier, Husky + lint-staged
- npm-скрипты: `npm start`, `npm build`, `npm test`, `npm lint`, `npm run prettier`

## 🏗 Архитектура и структура проекта
Проект разработан с использованием архитектуры FSD (Feature-Sliced Design).

Структура приложения организована по основным слоям `src/app`: `pages`, `widgets`, `features`, `entities` и `shared`, что позволяет разделять бизнес-логику, UI-компоненты и общие сервисы.

## 🔐 Переменные окружения

Проект использует Supabase через `src/environments/environment.ts` (в коде обращение — `environment.supabaseUrl` и `environment.supabaseKey`).

Рекомендации:
- Не хранить реальные ключи в репозитории. В текущей ветке есть заполненные поля в `src/environments/environment.ts` — лучше заменить их на переменные окружения на этапе сборки.
- Для локальной разработки можно использовать `.env` или локальные файлы окружения, но НЕ коммитить секреты в Git.

Пример (не добавляйте реальных ключей в репозиторий):

```ts
// src/environments/environment.ts (пример)
export const environment = {
  production: false,
  supabaseUrl: process.env['SUPABASE_URL'] || '',
  supabaseKey: process.env['SUPABASE_KEY'] || '',
};
```
